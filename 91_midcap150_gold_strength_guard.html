Midcap150 Momentum 10 — Gold-Strength Guard on Report 48

Report 48's exact design, with one change: during a risk-off period (NIFTY below its 200-day EMA), the hedge sleeve holds gold ONLY while gold itself passes two checks — its own 126-day (~6-month) return beats NIFTY's 126-day return, AND that return is positive. Whenever either check fails, the hedge sleeve sits in flat 0%-return cash instead of gold for that day. This guard never adds leverage or a third asset — it only ever replaces gold with cash — so any improvement has to come from avoiding gold's own bad stretches, not from gold earning something better. CORRECTED after report 99's timing audit — the first release of this page claimed +11.5pp of CAGR from an execution-timing artifact; every number below is the corrected one, and the lead panel explains what changed.

▲ corrected — a timing fix removed a phantom +11.5pp; what remains is a small, real drawdown tool

As first published, this page showed CAGR jumping from ~43.3% to ~54.8% with the guard. That version was wrong: it credited the guard with gold (or flat cash) on the regime flip-off day itself — a day whose realized return in report 48 is still stocks, because the switch executes at that day's close — and its exit checks used the same day's close. On 2015-08-24 alone (−11.3% in stocks) the old code charged +1.2% gold. Report 99 (“Timing Audit — the Gold-Strength Guard's +11.5pp That Wasn't”) breaks this down day by day. Corrected, the honest numbers are:

CAGR +42.0% (report 48, unconditional gold) → +42.3% (+0.30pp — essentially unchanged), while max drawdown improves from -24.3% to -22.6% — a real but modest defensive edge, not a return engine.

Mechanically the guard still does what it was built to do: 259 of 1074 regime-off days sit in flat cash instead of gold, and the cash-block breakdown below shows which historical periods those days came from.

Limitations

▲ read before trusting any number above

WHAT THIS SHOWS — every simplification behind this backtest.

  • Zero transaction costs on the extra gold↔cash switches this guard introduces beyond report 48's own switching. At the corrected scale (+0.3pp CAGR, ~1.7pp drawdown), those costs plausibly absorb the CAGR part entirely — treat the guard as a small drawdown tool, not a return one. Report 89 found even 0.1% slippage costs report 48 itself ~2.6 points of CAGR.
  • Timing convention (the report 99 fix): every guard decision uses only data through the PRIOR close, matching report 48's own close-execution convention — a day's realized return belongs to the state decided at the previous close. The first release of this report used same-day information and overstated the effect by roughly 100×; the corrected implementation lives in backtest91.build_gold_strength_guard, and report 99 quantifies the before/after.
  • The guard's "beats NIFTY" and "is positive" checks both use the same 126-day lookback — this specific window wasn't tuned or compared against other lookback lengths here; a different window could move the result in either direction.
  • Flat cash earns literally 0% here, same convention as report 48's own cash-based variants — a liquid fund or short-term debt instrument (reports 68/69/70 assumed ~6%) would likely improve this further, untested in this report.
  • Today's fixed Midcap150 constituent list is applied retroactively across the whole window (survivorship bias). Equal weighting, no F&O-eligibility screen, unadjusted prices, no dividends modeled — same as every other reconstruction here.
