First published, this report showed the guard adding 11.3–11.9pp of CAGR on every single calendar. The flatness of that band was the tell: report 99 traced it to an execution-timing bug — the guard was collecting gold (or cash) on the regime flip-off day itself, whose realized return in report 48 is still stocks, and its exit checks used the same day's close. Corrected, the pattern that survives is still remarkably uniform — +0.43pp to +0.44pp across all six calendars — but small. The uniformity is real and explainable: the guard acts purely on the hedge leg, and the regime and gold inputs are identical on every calendar; only the stock re-selection changes.

Drawdown is unchanged on 0 of the six calendars and 1.67–2.62pp shallower on the other 6 (Jun/Dec and Aug/Feb) — a modest defensive edge at essentially zero CAGR cost, not the return engine the first release advertised.

Limitations

▲ read before trusting any number above

WHAT THIS SHOWS — every simplification behind this backtest.

  • Same limitations as report 91 apply to every calendar here: zero transaction costs on the guard's extra gold↔cash switches — and at the corrected scale (+0.4pp CAGR), those costs plausibly consume the CAGR part entirely; the guard is best read as a free-to-cheap drawdown trim. The 126-day lookback wasn't tuned or compared against alternatives, and flat cash earns literally 0% rather than a liquid-fund yield.
  • Timing convention: every guard decision here uses only data through the PRIOR close (report 99's fix). The first release of this report used same-day information — most visibly, flipping the guard's position on the same close that tripped the check — and its +11.3-11.9pp band was the artifact.
  • This report's window (2009-02-27 onward) is narrower than report 91's own single-calendar window (2009-01-02 onward) because it's restricted to the overlap across all six calendars' own first-valid- rebalance dates at once — same convention report 85 used for report 48 itself.
  • Today's fixed Midcap150 constituent list is applied retroactively across the whole window (survivorship bias). Equal weighting, no F&O-eligibility screen, unadjusted prices, no dividends modeled — same as every other reconstruction here.
